# DBT Conventions — JFrog Artifactory Analytics

These conventions apply to all Gold layer DBT models generated by this pipeline.
The modeling agent must follow them. The review agent validates against them.

---

## Model Naming

| Layer | Prefix | Example |
|---|---|---|
| Gold fact | `gold_fact_` | `gold_fact_artifact_usage_daily` |
| Gold dimension | `gold_dim_` | `gold_dim_repository` |
| Gold aggregate | `gold_` (no fact/dim) | `gold_package_downloads_daily` |

File names use snake_case. No abbreviations unless they are industry-standard (e.g. `sql`, `yml`, `dbt`).

## Materialization

| Model type | Materialization | Rationale |
|---|---|---|
| Fact tables (daily grain) | `incremental` | Append new dates; avoid full scans |
| Dimension tables | `table` | Rebuilt daily; small enough |
| Gold aggregates | `incremental` | Same as fact |

Incremental strategy: `delete+insert` on `unique_key`.

## Grain Documentation

- Every model must have an explicit grain statement.
- In SQL: first comment on line 1: `-- Grain: one row per (col1, col2, col3)`
- In YAML: `description` must start with the grain statement as the first sentence.

## unique_key

- Must be a list in YAML config, never a single string.
- Must match the grain components exactly.
- Must match the GROUP BY clause in the SQL.

## Required Tests

| Column type | Required test |
|---|---|
| All grain key columns | `not_null` |
| Dimension natural keys | `unique` + `not_null` |
| Enum columns (actor_type, repository_mode, package_type) | `accepted_values` |
| Measure columns | No test required (they can be 0) |

## CTE Naming Convention

Use prefixed CTE names to communicate purpose:

| Prefix | Purpose |
|---|---|
| `stg_` | Staging — parse raw, type cast, filter |
| `deduped_` | Deduplication step |
| `classified_` | Actor/entity classification |
| `enriched_` | Metadata join (repository, artifact) |
| `typed_` | Event type flagging (download vs. upload) |

## Column Descriptions in YAML

- All grain key columns must have descriptions.
- All measure columns must have descriptions explaining the computation.
- All denormalized dimension columns must note they are denormalized and from which source.

## SELECT Rules

- No `SELECT *` in any final SELECT.
- All column names must be explicitly listed.
- Use `AS` aliases for all computed columns.
- Align column names and AS aliases vertically for readability (not required by linter, but preferred).
